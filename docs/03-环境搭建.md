# 03 - 环境搭建

> 从一台「装了 Linux 和显卡驱动的空机器」开始，到「能跑通一次模型自检」。
> 全部操作由 [scripts/server_setup.sh](../scripts/server_setup.sh) 一个脚本完成，
> 这篇逐段讲**它为什么这么写**。

---

## 0. 前提：机器上得先有什么

| 前提 | 怎么确认 | 没有怎么办 |
|---|---|---|
| Linux（本项目用 Ubuntu 22.04） | `cat /etc/os-release` | — |
| NVIDIA 显卡 + 驱动 | `nvidia-smi` 能打印出显卡型号 | 装驱动（这一步通常得管理员来） |
| 能上网（至少能访问镜像站） | `curl -I https://mirrors.tuna.tsinghua.edu.cn` | 配置代理 |
| 一个可写的大磁盘 | `df -h` | 见 §5 |

本项目目标机器：

```
6 × RTX 4090 (24 GB)  |  128 核 CPU  |  503 GB 内存  |  /root/Test 203 GB 可写
```

跑训练**最少一张 24 GB 的卡**；装环境本身不需要 GPU。

> `nvidia-smi` 右上角会显示 `CUDA Version: 12.4` 之类。注意那**不是**你装的 CUDA 版本，
> 而是**驱动最高支持的 CUDA 版本**。PyTorch 自带的 CUDA 运行时不能超过它，
> 这就是本项目选 `cu124` 的原因（驱动 550 最高支持 cu124）。

## 1. 一键安装

```bash
# 在服务器上
cd /root/Test/mini-r1        # 或者你自己的项目目录
bash scripts/server_setup.sh
```

脚本是**幂等**的（`set -euo pipefail` + 每步先检查），
重复执行不会重复下载，中途失败可以直接再跑一遍。

跑完之后会打印一段验证信息：

```
=== 验证 ===
torch: 2.6.0+cu124
cuda available: True
gpu count: 6
  GPU0: NVIDIA GeForce RTX 4090 25.3GB
  ...
transformers: 4.51.3 | datasets: 3.x.x
=== SETUP DONE ===
```

`cuda available: True` 是**唯一的硬性验收标准**。如果是 `False`，
先看 [08-排错FAQ](08-排错FAQ.md)，不要继续往下走。

## 2. 逐段拆解

### 2.1 为什么用 conda，而且装在项目目录里

```bash
BASE=/root/Test/mini-r1
MF=$BASE/miniforge
export PIP_CACHE_DIR=$BASE/.cache/pip
```

三个决定，各有原因：

**① 不用系统自带的 Python。**
系统 Python 被操作系统自己的工具依赖着（`apt`、`yum` 之类都是 Python 写的），
往里装 `torch` 可能把系统搞坏；反过来系统升级也可能把你的环境搞坏。

**② 不用 `venv`，用 `conda`。**
`venv` 只能隔离 Python 包，管不了**非 Python 的依赖**（比如 CUDA 运行库、
编译好的二进制）。conda 可以。而且本项目要在同一台机器上装多套互不干扰的环境时，
conda 更省事。

**③ 装在 `/root/Test/mini-r1/miniforge` 而不是默认的 `~/miniforge3`。**
因为系统盘（`/`）只有 48 GB 空闲，而 conda 环境 + 各种缓存轻松吃掉 10 GB。
`/root/Test` 才是那块 203 GB 的大盘。**这是本项目的硬性约束，不是偏好。**

```bash
export HF_HOME=$BASE/.cache/huggingface
```
HuggingFace 的模型/数据集缓存默认在 `~/.cache/huggingface`，会撑爆系统盘，
所以改到项目盘。

### 2.2 装 miniforge（用清华镜像，失败回退官方源）

```bash
if [ ! -x "$MF/bin/conda" ]; then
  curl -sL --connect-timeout 20 -o /tmp/mf.sh \
    https://mirrors.tuna.tsinghua.edu.cn/github-release/conda-forge/miniforge/LatestRelease/Miniforge3-Linux-x86_64.sh \
    || curl -sL -o /tmp/mf.sh \
    https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-Linux-x86_64.sh
  bash /tmp/mf.sh -b -p "$MF"
  ...
```

- `miniforge` 是 conda 的一个发行版，默认只用 `conda-forge` 这个社区源
  （不像 Anaconda 官方源有商业授权限制），做研究更省心。
- `-b` = 静默安装（不问「是否同意协议」），`-p` = 装到指定路径。
- 先试清华镜像，失败（`||`）再试 GitHub 官方 —— 国内直连 GitHub 经常抽风。
  **这个「先镜像后官方」的模式在本项目里到处都是**，是个值得学的习惯。

```bash
"$MF/bin/conda" config --add channels https://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud/conda-forge/
```
把清华源加到 conda 的频道列表里，以后装包自动走镜像。

### 2.3 建环境（注意那个 `-p`）

```bash
CONDA_ENVS_PATH="$MF/envs" "$MF/bin/conda" create -p "$MF/envs/$ENV_NAME" -y python=3.10
```

**这里是最容易踩的坑**。通常你会写：

```bash
conda create -n mini-r1 python=3.10        # ❌ 在本项目里会失败
```

因为这台机器的系统 `.condarc` 里配了 `envs_dirs` 指向一个**只读盘**，
`-n`（按名字建）会落到那个只读目录里，报权限错误。
所以必须用 **`-p`（按完整路径建）** 显式指定位置。

后果：以后所有命令都不能用 `conda activate`，而要用**绝对路径**调用：

```bash
# ❌ 需要先 conda activate
miniforge/envs/mini-r1/bin/python src/train_sft.py

# ✅ 本项目的写法：直接写解释器的全路径
/root/Test/mini-r1/miniforge/envs/mini-r1/bin/python src/train_sft.py
```

你在 [run_sft.sh](../scripts/run_sft.sh)、[launch.sh](../scripts/launch.sh)
里看到的 `$PROJ/miniforge/envs/mini-r1/bin/python` 就是这个原因。
好处是脚本不依赖「当前有没有 activate 过环境」，扔进 `nohup` 里也不会出问题。

Python 版本选 **3.10**：够新（支持 `str | None` 这类类型语法，
[src/train_grpo.py](../src/train_grpo.py) 用到了），又足够稳。

### 2.4 装 PyTorch

```bash
"$PIP" install --quiet torch==2.6.0 torchvision==0.21.0 \
  --index-url https://mirrors.tuna.tsinghua.edu.cn/pytorch-wheels/cu124 \
  || "$PIP" install --quiet torch==2.6.0 torchvision==0.21.0 \
  --index-url https://download.pytorch.org/whl/cu124
```

- **`cu124` 不是随便选的**：要和驱动能力匹配（见 §0）。
  装错版本的症状是 `torch.cuda.is_available()` 返回 `False`，
  或者报 `The NVIDIA driver on your system is too old`。
- `--index-url` 指向 PyTorch 官方 wheel 源（清华有镜像），
  **不要从 PyPI 装 `torch`** —— PyPI 上那个版本常常不含 CUDA。
- 版本钉死 `2.6.0`：这个版本 `torch.load` 默认 `weights_only=True`
  （一个安全变更），本项目的检查点已经验证过能正常加载。换版本要重新验证。

### 2.5 其余依赖

```bash
"$PIP" install --quiet numpy tqdm datasets tokenizers wandb sentencepiece \
  transformers==4.51.3 accelerate
```

| 包 | 用来干什么 | 本项目哪里用到 |
|---|---|---|
| `numpy` | 数组运算；`np.memmap` 读数据分片 | [data_pretrain.py](../src/data_pretrain.py), [train_pretrain.py](../src/train_pretrain.py) |
| `tokenizers` | **HuggingFace 的 Rust 分词库**，训练 BPE、批量编码 | [tokenizer_train.py](../src/tokenizer_train.py), 全部训练脚本 |
| `datasets` | 读 parquet / json 数据集 | 读 OpenHermes、GSM8K |
| `pyarrow` | parquet 底层（`datasets` 的依赖，也被直接用到） | [data_pretrain.py](../src/data_pretrain.py) |
| `transformers` | **本项目没用它的模型**，只有部分工具链依赖它 | 间接依赖 |
| `tqdm` / `wandb` / `sentencepiece` / `accelerate` | 本项目**没有实际使用**，是历史遗留的依赖 | — |

> 📌 **值得注意**：这个依赖列表**偏胖**。真正的核心依赖只有
> `torch` / `numpy` / `tokenizers` / `pyarrow` / `datasets` 五个。
> 如果你要复现，可以先只装这五个，跑不动再补。

### 2.6 flash-attn（可选加速）

```bash
"$PIP" install --quiet flash-attn==2.7.4.post1 --no-build-isolation || \
  echo "WARN: flash-attn 安装失败, 将使用 PyTorch 原生 SDPA"
```

**flash-attn 是注意力的一个高速实现**，能省显存、提速度。
但它装起来很麻烦（要现编译，动辄一小时），所以脚本让**失败也继续**。

不装也能跑：[src/model.py](../src/model.py) 的注意力用的是
`F.scaled_dot_product_attention`（SDPA），
PyTorch 会在可用时**自动选择** flash 内核 —— 也就是说，装了 flash-attn
PyTorch 也能用上它，没装就退回到「内存高效内核」，功能完全一样，只是慢一点。

**这就是「优雅降级」**：核心功能不依赖可选加速库。

## 3. 环境变量：HuggingFace 镜像

国内直连 `huggingface.co` 基本不可用，本项目统一走镜像：

```bash
export HF_ENDPOINT=https://hf-mirror.com
export HF_HOME=/root/Test/mini-r1/.cache/huggingface
```

[scripts/launch.sh](../scripts/launch.sh) 帮你设好了这两个变量：

```bash
export HF_HOME=$PROJ/.cache/huggingface
export HF_ENDPOINT=https://hf-mirror.com
export HF_HUB_DOWNLOAD_TIMEOUT=60
setsid nohup $PROJ/miniforge/envs/mini-r1/bin/python -u "$@" > $PROJ/logs/$NAME.log 2>&1 &
```

⚠️ 但**镜像不是万能的**：hf-mirror 的部分 API 会 302 跳回 `huggingface.co`
（然后就被墙了），`datasets` 跟随重定向就会崩。
本项目的解法是**先用 curl 把文件下到本地，再读本地文件** ——
详见 [05-数据管线](05-数据管线.md#3-为什么不用-datasets-直接下载)。

## 4. 验收清单

装完之后，逐条打勾：

```bash
PY=/root/Test/mini-r1/miniforge/envs/mini-r1/bin/python

# ① Python 版本对
$PY --version                                   # 期望: Python 3.10.x

# ② torch 能看见 GPU（★ 最重要）
$PY -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.device_count())"
#   期望: 2.6.0+cu124 True 6

# ③ 模型代码本身没问题（用随机数据跑一次前向+反向+采样，CPU 也能跑）
cd /root/Test/mini-r1 && $PY src/model.py
#   期望: 参数量: 407.4M ... 前向+反向 OK, loss = 11.xxxx ... 采样 OK

# ④ 分词器在不在
ls -lh tokenizer/tokenizer.json                 # 期望: 约 11 MB

# ⑤ 数据在不在
ls data/train/ | wc -l                          # 期望: 100（个分片）
```

第 ③ 步特别值得注意：**[src/model.py](../src/model.py) 的末尾有一段
`if __name__ == "__main__":` 自检代码**。它不是装饰，是让你能在
「还没有数据、还没有分词器」的时候就能确认模型代码是对的。
**自己写代码时也该留这么一段** —— 它把「模型写错了」和「数据有问题」
这两类故障分开了，省下大量排查时间。

还有一个显存探针：

```bash
$PY scripts/probe_mem.py           # 跑一步完整的训练，报告实际峰值显存
```

见 [06-训练与评测](06-训练与评测.md#5-显存账本这一节能省你几个小时)。

## 5. 磁盘怎么分配

装机时就该想好的事。本项目的实测占用：

| 目录 | 大小 | 内容 |
|---|---|---|
| `miniforge/` | ~7 GB | conda 环境 |
| `data/raw/` | 29 GB | 原始 parquet（FineWeb-Edu 14 个 + GSM8K + OpenHermes） |
| `data/train/` + `val.bin` | 37 GB | 分好词的 100 个 `.bin` 分片 |
| `ckpts/` | ~15 GB | 预训练 4.9G + SFT 4.9G(+最终 1.6G) + GRPO |
| `tokenizer/` | 11 MB | `tokenizer.json` |
| `.cache/` | 若干 GB | HF 缓存、pip 缓存 |

**合计约 90 GB。** 系统盘只有 48 GB，所以**必须**全部放在大盘上。

想省空间的话：数据管线跑完之后 `data/raw/` 里的 FineWeb parquet（29 GB）
理论上可以删（分片是从它生成的），但建议留着 —— 想改分词器重跑管线时不用重新下载。

## 6. 如果你是复现者（不是在本项目的服务器上）

几个**路径写死**的地方需要改：

```bash
grep -rn "/root/Test/mini-r1" scripts/ src/ | head -30
```

主要集中在这几类：

1. **脚本开头的 `PROJ=/root/Test/mini-r1`** —— 改成你的目录
2. **Python 参数的默认值**，例如
   [train_sft.py](../src/train_sft.py#L92) 的 `--tokenizer` 默认值
   （不过所有脚本都会显式传参，所以通常不用改）
3. **`--base_ckpt` 之类的输入路径** —— 由调用方传入

一个好习惯：**在脚本里只写一次路径**，其他地方引用那个变量
（本项目的 `PROJ=/root/Test/mini-r1` 就是干这个的）。
如果发现某个脚本里路径散落各处，那是重构的信号。
